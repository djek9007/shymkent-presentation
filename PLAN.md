# ТЗ: централизованная платформа сайтов школ и дошкольных организаций

## 1. Цель и границы MVP

Создать единую платформу, на которой школы и дошкольные организации самостоятельно ведут свои публичные сайты.

- Центральный портал: `school.edu.gov.kz`.
- Сайты организаций: `<идентификатор>.school.edu.gov.kz`.
- Первый запуск: до 100 организаций.
- Единый дизайн и структура сайтов.
- Казахский и русский языки.
- Добавление организации без изменения кода и отдельного развёртывания.

MVP не включает электронный дневник, оценки, личные кабинеты учащихся и родителей, приём платежей и интеграции с образовательными системами.

## 2. Пользователи и управление

### Центральный администратор

- Создаёт, редактирует и отключает организации.
- Указывает тип организации: школа или дошкольная организация.
- Назначает уникальный идентификатор поддомена.
- Создаёт учётную запись сотрудника организации и выдаёт логин и временный пароль.
- Сбрасывает пароль при необходимости.
- Имеет доступ к содержимому всех организаций.
- Публикует общие новости и материалы центрального портала.

### Сотрудник организации

- Входит в общую панель управления.
- При первом входе меняет временный пароль.
- Редактирует только материалы своей организации.
- Самостоятельно публикует материалы без согласования центром.
- Создаёт черновики, изменяет и снимает материалы с публикации.
- Меняет собственный пароль.

В MVP достаточно одной учётной записи сотрудника на организацию. Модель данных должна позволять позже добавлять несколько сотрудников.

### Посетитель

Без регистрации просматривает центральный портал, каталог и опубликованные материалы организаций.

## 3. Состав сайтов и работа с контентом

### Центральный портал

- Главная страница с описанием проекта.
- Каталог организаций с поиском по названию и номеру, фильтром по типу.
- Общие новости.
- Общие документы и материалы.
- Ссылка на вход в панель управления.

В каталоге отображаются только активные организации.

### Сайт организации

- Главная: название, логотип, краткая информация и последние новости.
- О школе / об организации.
- Администрация.
- Учителя / педагоги.
- Новости: список и отдельные страницы.
- Документы: название, описание и скачивание файла.
- Галерея: альбомы с фотографиями и подписями.
- Расписание.
- Контакты: адрес, телефон, электронная почта и ссылка на карту.

Сотрудник может скрыть необязательный раздел, например расписание у дошкольной организации. Расположение и оформление разделов задаются общим шаблоном; отдельный конструктор страниц в MVP не нужен.

### Редактирование

- Текстовые поля с базовым форматированием: заголовки, списки, ссылки.
- Загрузка изображений и документов.
- Предпросмотр перед публикацией.
- Порядок отображения сотрудников, документов и альбомов.
- Общие контакты и логотип организации редактируются отдельно от страниц.
- Произвольные HTML и JavaScript в содержимом запрещены.

### Языки

- Интерфейс сайта доступен на казахском и русском.
- Переводимые материалы имеют отдельные поля для обоих языков.
- Переводы заполняются сотрудниками; автоматический перевод не входит в MVP.
- Материал можно опубликовать на одном языке. На другом языке показывается сообщение, что перевод ещё не добавлен.
- Язык по умолчанию — казахский.

### Расписание

В MVP сотрудник загружает PDF, указывает название и дату обновления. Посетитель может открыть или скачать файл.

Расписание хранится как отдельная сущность. В следующей версии к нему можно добавить редактируемые записи без изменения адреса раздела и удаления ранее загруженных PDF.

## 4. Техническая реализация

### Архитектура и стек

Для быстрой самостоятельной реализации использовать:

- Go: HTTP-сервер и маршрутизация на стандартном `net/http`.
- Vue 3 + TypeScript + Vite: весь интерфейс центрального портала, сайтов организаций и панели управления.
- Vue Router для маршрутов; PrimeVue для готовых компонентов панели управления.
- PostgreSQL.
- Go предоставляет JSON API по `/api/v1/`; Vue обращается к нему на том же домене.
- Nginx отдаёт сборку Vue и проксирует API и запросы файлов в Go.
- Локальное хранилище загрузок; в базе сохраняются метаданные файлов и их относительные пути, а не абсолютные публичные URL.

Один репозиторий, одна база данных, один Go-сервис и одна сборка Vue обслуживают все организации. Node.js нужен только для сборки frontend. Отдельных приложений для каждой школы нет.

### Интерфейс и расход ресурсов

- В MVP Vue работает как SPA: получает данные из Go API и отображает страницы в браузере. JavaScript обязателен. SSR и предварительная генерация страниц не входят в MVP; полная индексация поисковиками не является критерием приёмки первой версии.
- Публичные маршруты и панель разделяются на лениво загружаемые части. PrimeVue и редактор не загружаются при посещении публичных страниц.
- Использовать готовый редактор с базовым форматированием; собственный редактор не разрабатывать.
- Формы показывают ошибки серверной валидации. Для запросов предусмотрены состояния загрузки, ошибки с повторной попыткой и пустого результата.
- Общие стили и скрипты кэшируются браузером. Фотографии получают уменьшенные версии для списков и галерей, размеры в HTML и отложенную загрузку вне первого экрана.
- Бюджет первой загрузки публичного маршрута: до 200 КБ JavaScript и до 100 КБ CSS после gzip, включая зависимости, без изображений и документов. Размер панели измеряется отдельно.

### API и маршрутизация

- Публичный API предоставляет сведения о текущем сайте, опубликованные материалы, каталог и поиск. Списки имеют пагинацию.
- Административный API предоставляет вход, выход, управление паролями и операции с организациями, контентом и файлами. Загрузка файлов использует `multipart/form-data`.
- На поддоменах организация определяется Go-сервером по проверенному имени хоста. В панели на центральном домене доступ определяется пользователем и его правами; идентификатор из запроса не является разрешением на доступ.
- API возвращает `401` без авторизации, `403` при запрете доступа, `404` для отсутствующего ресурса и `422` для ошибок полей. В Vue нет собственной логики разрешения доступа к данным.
- Прямой переход и обновление вложенных маршрутов Vue работают через SPA fallback в Nginx. Fallback не применяется к API и файлам. Неизвестные и отключённые поддомены отклоняются до отдачи SPA.

### Панель управления и авторизация

- Вход, выход, обязательная смена временного пароля, смена собственного пароля и сброс пароля центральным администратором реализуются в Go-приложении.
- Использовать серверные сессии с хранением в PostgreSQL и случайным непрозрачным идентификатором в cookie. Cookie: `Secure`, `HttpOnly`, `SameSite=Lax`, без атрибута `Domain`, с `Path=/`.
- При входе и смене пароля обновлять идентификатор сессии; при выходе удалять сессию, при сбросе пароля и отключении организации отзывать все соответствующие сессии.
- Все изменяющие запросы требуют проверки CSRF и прав на организацию. До смены временного пароля доступны только смена пароля и выход.

### Организации и изоляция данных

- Организация определяется по точному соответствию поддомена записи в базе.
- Все материалы, загрузки и учётные записи привязаны к организации.
- Доступ сотрудника ограничивается на сервере, включая прямые запросы по идентификаторам.
- Общие материалы центрального портала отделены от материалов организаций.
- Неизвестный или отключённый поддомен возвращает страницу 404.
- Отключение организации закрывает публичный сайт и вход её сотрудников, сохраняя данные.

Основные сущности: организация, пользователь, страница, новость, сотрудник, документ, альбом, фотография и расписание.

### Поддомены и HTTPS

- Центральный администратор задаёт уникальный идентификатор поддомена.
- Для школы допустим идентификатор `51`.
- При совпадении номеров используются различимые идентификаторы, например `school-51-almaty` и `sad-51-almaty`.
- Идентификатор содержит только латинские буквы, цифры и дефисы.
- Поддомены `www`, `admin` и `api` зарезервированы.
- После создания организации идентификатор в MVP не меняется.
- Настроить DNS для центрального домена и wildcard-поддоменов.
- Настроить HTTPS для `school.edu.gov.kz` и `*.school.edu.gov.kz`.
- Панель управления доступна на `school.edu.gov.kz/admin/`; сессия авторизации ограничена центральным доменом.

Доступ к DNS и право использования домена предоставляет заказчик.

### Безопасность и эксплуатация

- Пароли хранятся только в виде хешей.
- Обычные поля выводятся средствами экранирования Vue. Форматированный текст очищается на Go-сервере по разрешённому набору тегов и атрибутов; `v-html` допускается только для очищенного содержимого.
- Для хеширования паролей, доступа к PostgreSQL и очистки HTML использовать поддерживаемые библиотеки.
- Защита форм от CSRF и ограничение повторных попыток входа.
- Разрешённые изображения: JPEG, PNG, WebP, до 10 МБ.
- Документы: PDF, DOCX, XLSX, до 20 МБ; расписание — только PDF.
- Проверка расширения и типа файла; загружаемые файлы не исполняются сервером.
- Черновики и их вложения недоступны без авторизации.
- Ежедневное резервное копирование базы и загрузок; хранение копий 14 дней отдельно от сервера приложения.
- Журнал ошибок и проверка доступности центрального портала.
- Секреты задаются через окружение и не включаются в репозиторий.

## 5. Проверка и критерии приёмки

MVP считается готовым, когда:

- Администратор создаёт школу и дошкольную организацию, выдаёт им учётные записи.
- Их сайты открываются на отдельных поддоменах без изменения кода.
- Сотрудники меняют временные пароли и самостоятельно публикуют контент.
- Сотрудник одной организации не может читать черновики или изменять данные другой, включая обращения по прямым URL.
- Работают все заявленные разделы, поиск и фильтр каталога.
- Работают оба языка и корректно обозначаются отсутствующие переводы.
- PDF расписания загружается, заменяется и скачивается.
- Черновики скрыты от посетителей; опубликованные материалы видны.
- Отключённые организации исчезают из каталога и недоступны на своих поддоменах.
- Сайты удобно использовать на телефоне и компьютере.
- Прямой переход и обновление вложенных адресов работают. При ошибках API отображаются понятные сообщения, при пустых списках — соответствующее состояние.
- Панель и редактор не входят в первоначальную загрузку публичного сайта. Проверены бюджеты CSS и JavaScript.
- Проверены смена временного пароля, выход, отзыв сессий, CSRF-защита и удаление опасной разметки из форматированного текста.
- HTTPS работает на центральном портале и поддоменах.
- Выполнено пробное восстановление базы и файлов из резервной копии.
- Проведён нагрузочный тест на данных 100 организаций и с 50 одновременными посетителями: без серверных ошибок, 95% ответов API чтения — не дольше 2 секунд, без учёта скачивания файлов. Этот показатель не заменяет проверку загрузки интерфейса в браузере.

## 6. Порядок реализации и расширение

1. Создать Go-приложение, SQL-миграции PostgreSQL, модели организаций, пользователей, сессии и разграничение доступа.
2. Реализовать JSON API, определение организации по поддомену и проверку прав.
3. Создать Vue-приложение: центральный портал, каталог и общий дизайн сайтов организаций.
4. Добавить панель на PrimeVue, разделы, двуязычный контент, загрузки и публикацию.
5. Настроить DNS, HTTPS, резервное копирование и провести приёмочные проверки.

Следующие версии: редактируемое расписание, несколько сотрудников с разными правами, согласование публикаций, история изменений и перенос файлов в объектное хранилище. Эти функции не реализуются заранее, но привязка данных к организациям и отдельная сущность расписания сохраняют возможность расширения.
