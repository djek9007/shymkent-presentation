# БІЛІМ: платформа сайтов образовательных организаций

Реализация `../PLAN.md`: один Go-сервис, одна база PostgreSQL и одна Vue SPA. Презентация `../index.html` сохранена отдельно.

## Локальный запуск

### Полностью через Docker

Из `platform/` выполните:

```sh
docker compose -f deploy/compose.local.yaml up -d --build --wait
```

Портал: `http://school.localhost:5173/`, центральная панель: `http://school.localhost:5173/admin/`. Админка школы №51: `http://demo-school-51.school.localhost:5173/admin/`.
Миграция и заполнение демо-данными выполняются автоматически. Логин администратора
`demo.admin`, общедоступный демонстрационный пароль `Demo-Access-2026!`.
База и загрузки сохраняются в отдельных Docker volumes. HTTP доступен только
на `127.0.0.1:5173`, база и API не публикуют порты. Конфигурация и встроенный
пароль базы предназначены только для локальной демонстрации.

```sh
docker compose -f deploy/compose.local.yaml logs --tail=50
docker compose -f deploy/compose.local.yaml down
```

Остановка сохраняет данные; не добавляйте `-v`, если их нужно оставить.

### Без контейнеров приложения

Требуются Go 1.27+, Node.js 22.12+, PostgreSQL 18 (или Docker), инструменты PostgreSQL для резервного копирования. Все команды выполняются из `platform/`.

1. Создайте пустую базу `school`. Для Docker: задайте `POSTGRES_PASSWORD` в окружении и запустите `docker compose -f deploy/compose.yaml up -d`.
2. Задайте окружение, подставив свои значения:

```sh
export DATABASE_URL='postgres://school:YOUR_PASSWORD@127.0.0.1:5432/school?sslmode=disable'
export BASE_DOMAIN=school.localhost
export DEV_HTTP=1
export UPLOAD_DIR="$PWD/var/uploads"
go build -buildvcs=false -o bin/server ./cmd/server
bin/server migrate
```

3. Создайте центрального администратора. Пароль не передавайте аргументом командной строки:

```sh
read -rs ADMIN_PASSWORD
export ADMIN_PASSWORD
bin/server create-admin admin
unset ADMIN_PASSWORD
bin/server
```

4. В другом терминале:

```sh
cd web
npm ci
npm run dev
```

Откройте `http://school.localhost:5173`, панель — `/admin/`. При необходимости добавьте `127.0.0.1 school.localhost 51.school.localhost sad-51.school.localhost` в hosts. После создания организации `51` её сайт работает на `http://51.school.localhost:5173` без пересборки. `.localhost` автоматически разрешается современными браузерами; hosts нужен для клиентов, которые этого не делают.

## Работа в панели

Центральный администратор создаёт организацию и добавляет сотрудников на отдельной странице `/admin/users` («Пользователи»). На странице есть поиск по логину/организации, пагинация, создание нескольких сотрудников одной организации, изменение логина, блокировка/разблокировка и отдельная кнопка сброса пароля. Изменение логина, блокировка и сброс пароля отзывают сессии. Временный пароль показывается один раз; сотрудник меняет его при первом входе. Учётные записи центральных администраторов видны в списке, но защищены от изменения в панели.

В разделе `/admin/menu` («Меню сайта») можно изменить названия ҚАЗ/РУС, видимость и порядок стандартных пунктов кнопками ↑/↓. Сначала выберите сайт в поле «Сайт». Настройки хранятся в PostgreSQL отдельно для портала и каждой организации; поле «URL-адрес» меняет адрес пункта: путь от `/` или полный адрес `http://` / `https://`. Пустой URL у стандартного пункта сохраняет его исходный путь. Кнопка «Добавить ссылку» создаёт дополнительный пункт с обязательным URL; его можно вложить в группу, перемещать и удалить. Группы раскрывают вложенное меню и не имеют URL. Главная всегда видна. Видимость задаётся в редакторе меню. Прежние скрытые разделы учитываются до первого сохранения меню; сохранённое меню становится основным источником навигации. Это управление навигацией, а не ограничение доступа к опубликованным материалам.

В разделе «Организации» доступны поиск и пагинация. Кнопка «Материалы» открывает контент выбранной организации, включая организации за первой страницей. Центральный портал содержит общие новости и документы; остальные разделы доступны на сайтах организаций.

У материалов отдельные поля ҚАЗ/РУС. Достаточно заголовка на одном языке; другой язык показывает отсутствие перевода. Предпросмотр очищает HTML на сервере без изменения статуса публикации. «Сохранить черновик / снять с публикации» скрывает материал и его вложения. Публикация происходит без согласования. Файлы загружаются в сохранённую запись. Для расписания новая загрузка заменяет прежний PDF; дату расписания укажите в отдельном поле; техническая дата записи меняется автоматически. Галерея — запись-альбом с фотографиями, подписями и порядком. Сотрудники администрации/педагоги — отдельные записи, допускают текст и фотографии. Описание документа задаётся форматированным текстом записи.

Настройки организации содержат контакты, двуязычные название/описание/адрес, логотип и скрываемые разделы. Поддомен после создания неизменяем. Отключение организации сохраняет данные, закрывает сайт и отзывает все сессии сотрудников.

## Проверки

```sh
go test ./...
go vet ./...
cd web && npm run build
```

Интеграционный тест требует **отдельную пустую** PostgreSQL БД: он создаёт таблицы и данные, непустую базу отклоняет.

```sh
TEST_DATABASE_URL='postgres://USER:PASSWORD@localhost/school_test?sslmode=disable' go test ./... -count=1 -v
```

Проверяет организации, Host, вход, обязательную смену пароля, ротацию/отзыв сессий, прямые ID чужих материалов, черновики и вложения, CSRF, очистку HTML, публикацию, отключение организации и выход. `scripts/check-budget.mjs` проверяет статические зависимости entry + Public по Vite manifest и gzip-бюджет; динамическая панель считается отдельно.

Нагрузка: подготовьте тестовую БД с 100 организациями, запустите сервис и `python3 scripts/load-test.py`. Переменные `LOAD_URL` и `LOAD_HOST` задают адрес/домен. Скрипт делает 1000 запросов с 50 клиентами и проверяет p95 ≤ 2 с.

## Production

- `BASE_DOMAIN=school.edu.gov.kz`; **уберите DEV_HTTP**. Сервис слушает только `127.0.0.1:8080`, наружу выходит через Nginx. Пользователь `school` имеет запись только в каталог загрузок. `DATABASE_URL` и остальные переменные храните в `/etc/school-platform.env` с правами 0600, не в репозитории.
- Соберите Go и `web/dist`. Установите `deploy/school-platform.service`; пути предполагают `/srv/school-platform`. Миграцию выполняйте до запуска службы; SQL идемпотентен для текущей первой версии схемы.
- DNS: A/AAAA для `school.edu.gov.kz` и `*.school.edu.gov.kz`. Wildcard-сертификат через ACME DNS-01 должен содержать оба имени. Право на домен, DNS API и сертификаты предоставляет заказчик.
- Подключите `deploy/nginx.conf` внутри `http {}` Nginx с модулем auth_request. Перед запуском выполните `nginx -t`. `/api/` и `/files/` никогда не попадают в SPA fallback; Host проверяется Go перед отдачей SPA и assets. Нет доверия произвольному X-Forwarded-Host. Nginx перезаписывает X-Real-IP для ограничения входов, прямой Go-порт снаружи закрыт.
- Go выводит ошибки в журнал службы (`journalctl -u school-platform`). Не журналирует пароли и cookie. Cookie Secure/HttpOnly/SameSite=Lax без Domain; срок сессии 12 часов.
- Ежедневно `scripts/backup.sh`: DATABASE_URL, UPLOAD_DIR, BACKUP_DIR. BACKUP_DIR должен быть смонтированным хранилищем **вне сервера приложения**, доступным только службе резервного копирования. Скрипт сохраняет dump, архив загрузок, SHA256SUMS; оставляет 14 дней. Хранилище должно иметь собственное шифрование/контроль доступа.
- `scripts/restore.sh BACKUP_DIRECTORY`: RESTORE_DATABASE_URL и RESTORE_UPLOAD_DIR должны быть пустыми. Скрипт проверяет суммы и отказывается перезаписывать существующие таблицы/файлы. Переключать трафик после проверки восстановленного приложения. Во время production-восстановления приложение остановлено.
- `scripts/maintenance.sh` ежедневно удаляет истёкшие сессии и счётчики входа. Заменённые/удалённые файлы остаются на диске для согласованности резервных копий; `scripts/prune-uploads.py` удаляет неиспользуемые файлы старше 15 дней, запускать при остановленном приложении.
- `scripts/monitor.sh` проверяет `/healthz` с таймаутом; задайте PORTAL_URL. Подключите к своему мониторингу/cron и настройте уведомление по ненулевому коду. Скрипты сами не отправляют сообщения.

Пример расписания cron (переменные задаёт защищённая обёртка или окружение службы): backup ежедневно в 02:00 UTC, maintenance в 02:30 UTC, monitor раз в 5 минут. Не вставляйте секреты в строку cron.

## Что проверено в этой среде

- PostgreSQL 18.6: миграция и интеграционный тест прошли.
- Go: тесты, vet, сборка. Vue: TypeScript и production build.
- Первичная публичная загрузка: около 42 КБ JS / 2,3 КБ CSS gzip; PrimeVue и Quill в отдельной динамической загрузке.
- 100 организаций / 50 клиентов / 1000 запросов: без ошибок, p95 41 мс на локальной машине. Это не гарантия производственного сервера.
- Пробный dump/restore: 100 организаций восстановлены в отдельную базу, контрольные суммы совпали; содержимое тестового файла после восстановления побайтово совпало.

Локально проверен Nginx 1.28.3 с тестовым TLS-сертификатом: вложенные маршруты возвращают SPA, неизвестный поддомен — 404, отсутствующие API и файлы — JSON 404 без fallback; защитные заголовки присутствуют. DNS, production HTTPS, внешний backup storage и Nginx на сервере заказчика ещё не настроены и не проверены. Полная production-приёмка требует этого доступа. SSR, электронный дневник, согласование публикаций, платежи и интеграции не реализованы согласно ТЗ.

Браузерная проверка Chromium: вход, открытие редактора, русский/казахский интерфейс, поиск 51, ширины 1440 и 390 px. Снимки сохранены в `output/playwright/`.

Для локальной БД выполните из `platform/` с настроенными DATABASE_URL и UPLOAD_DIR:

Команда добавляет четыре вымышленные организации, двуязычные материалы, закрытые черновики, новость без казахского перевода, три иллюстрации в каждой галерее, документы и PDF расписания. Файлы берутся из `fixtures/demo/`; внешние сервисы не используются. Для детсада расписание скрыто, отключённая школа не открывается публично.

Пароль **новых** тестовых аккаунтов: `Demo-Access-2026!`. Это общедоступный демонстрационный пароль, не использовать в production. Центральный администратор входит через `http://school.localhost:5173/admin/`; сотрудники — через `/admin/` на собственном школьном поддомене. Для `demo.school`: `http://demo-school-51.school.localhost:5173/admin/`; для `demo.preschool`: `http://demo-preschool-7.school.localhost:5173/admin/`; для `demo.first-login`: `http://demo-school-52.school.localhost:5173/admin/`. Сайты: `http://demo-school-51.school.localhost:5173/` и `http://demo-preschool-7.school.localhost:5173/`. Найдите «Демо» в каталоге или списке организаций панели.

Повторный запуск не изменяет существующие пароли, статусы организаций или текст материалов и не дублирует неизменённые примеры. Заголовки служат ключами демо-материалов: перед повторным заполнением сохраняйте их; изменение заголовка с сохранением прежнего вложения вызывает отказ и откат транзакции. Для `about` и `schedule` сохраняется существующая единственная запись. Команда отклоняет Secure/production-режим и нелокальный BASE_DOMAIN.

В текущую `school_preview` добавлены 4 организации, 46 материалов, 33 файла и 5 пользователей. Существовавшие 100 организаций, новость и пользователь `preview` сохранены.

## Тематика Шымкента

Публичный интерфейс и панель названы «Шымкент · Білім / Образование». Городской логотип в `web/public/shymkent-logo.svg` взят из [SVG на Wikimedia Commons](https://commons.wikimedia.org/wiki/File:Shymkent_logo.svg), где источником указан [официальный сайт акимата](https://www.gov.kz/memleket/entities/shymkent?lang=ru). SVG сохранён без изменения рисунка. Оформление на Vue: белый/светло-серый фон, синие элементы, красный акцент исходного логотипа. Прямое открытие gov.kz из среды заблокировано; точные CSS-цвета сайта не подтверждены, текущая синяя палитра приблизительная.

Демо-материалы посвящены образованию, краеведению и природе Шымкента. Реальные ориентиры — Қошқар ата и дендропарк — сверены с [официальным обзором городских объектов](https://www.gov.kz/memleket/entities/shymkent-turizm/press/article/details/198865). Организации, проекты, контакты и изображения остаются вымышленными и помечены как демо.

Новые локальные БД получают эту тематику через `seed-demo`. Для ранее заполненной локальной демо-БД: `psql "$DATABASE_URL" -X -v ON_ERROR_STOP=1 -f scripts/theme-shymkent.sql`. Скрипт обновляет только записи, точно совпадающие с исходными тестовыми данными; сохраняет изменённые пользователем тексты, ID, пароли и статусы. Старые заголовки поддерживаются при повторном `seed-demo`, без дублирования материалов.

## Вложенное школьное меню

Структура ориентируется на [школу №69 Астаны](https://69school-gymnaziya.edu.kz/akimshilik?lang=ru), [школу №3](https://mektep3-bilim.edu.kz/ru/) и [школу №2](https://2schoolastana.edu.kz/ru/): группировка сведений о школе, учебного процесса и школьной жизни. ## Отдельная админка каждой школы

Школьный администратор открывает `/admin/` на поддомене **своей** школы. Логин, сессия и повторная проверка учётной записи при создании сессии привязаны к ID организации, полученному из точного Host. Вход школьной учётной записью на центральном портале или чужом поддомене отклоняется. Центральная учётная запись работает только на BASE_DOMAIN; оттуда можно управлять выбранными организациями.

Cookie сессии host-only (без Domain), поэтому браузер не передаёт школьную сессию соседним школам. Сервер дополнительно отвергает сессию другой организации даже при ручном переносе cookie. Школьная панель показывает название школы, не предлагает выбор организации и содержит только её материалы, меню и настройки. Сотрудник может просматривать свои черновики и вложения через свой школьный домен. Смена временного пароля и выход тоже выполняются там.

На публичном сайте каждой школы появилась ссылка «Войти». Учётную запись создаёт центральный администратор в `/admin/users` и передаёт сотруднику адрес именно его школьной админки. Никаких новых паролей или изменений данных для перехода не требуется; прежний вход школьных сотрудников через центральную панель прекращён. Существующие host-only cookies центрального домена не переносятся: школьному сотруднику нужно войти на собственном поддомене.

Проверки отдельных админок: unit/integration Go + vet, Vue build; корректный школьный вход и отказ на центральном/чужом домене, перенос cookie между доменами, чужие ID, смена временного пароля и сессии, черновики и загрузки. Chromium: вход `demo.school` в собственную панель, сохранение меню, отказ с тем же логином на поддомене детсада, возвращение в сохранённую школьную сессию. Мобильная панель проверена при 390 px, снимки `output/playwright/school-admin-*.png`.
