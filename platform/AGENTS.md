# Проверенные решения и команды

- Платформа находится в `platform/`; исходная презентация `../index.html` остаётся самостоятельной.
- Go net/http + PostgreSQL; Vue 3 / TypeScript / Vite, Vue Router. PrimeVue и Quill загружаются только в панели.
- Центральный администратор входит только на BASE_DOMAIN, школьный — только на поддомене своей организации; логин и сессия проверяются по организации точного Host. Для локальной разработки BASE_DOMAIN=school.localhost и DEV_HTTP=1, в production DEV_HTTP запрещён.
- Библиотеки: pgx/v5, bcrypt, bluemonday, x/image; собственная криптография и очистка HTML не используются.
- `go test ./...` запускает проверки валидации. Интеграционная проверка требует TEST_DATABASE_URL отдельной пустой БД и создаёт в ней таблицы; непустую БД отклоняет.
- `go build -buildvcs=false -o bin/server ./cmd/server` работает и вне Git-репозитория.
- `cd web && npm ci && npm run build`: TypeScript, Vite, проверка gzip-бюджета публичного маршрута по manifest.
- Не читать .env, ключи и токены; секреты передаются окружением и не сохраняются в документах.
- Не отправлять исходники во внешние сервисы. Не изменять slug после создания организации.
- `deploy/nginx.conf` проверен через Nginx 1.28.3 с локальными портами/тестовым сертификатом: SPA fallback, 404 неизвестного Host, отсутствие fallback для API/файлов. Production-доступа к домену нет.
- `DEV_HTTP=1 BASE_DOMAIN=school.localhost bin/server seed-demo` добавляет локальные тестовые данные из `fixtures/demo/`, без сброса текущих паролей и текста материалов. Заголовки демо-материалов служат ключами повторного заполнения; менять их перед повторным seed нельзя. Пять логинов и общедоступный демонстрационный пароль описаны в README.
- Тематика платформы — город Шымкент. Городской логотип хранится в `web/public/shymkent-logo.svg`, источник и ограничение проверки палитры указаны в README. Демо-школы и контакты вымышлены; реальные городские ориентиры имеют источник в README.
- `scripts/theme-shymkent.sql` переводит исходные локальные демо-записи на тематику Шымкента по точному совпадению прежних значений, не меняя ID и пользователей. seed-demo распознаёт прежние заголовки региональных материалов.

- Меню: `site_settings(site_id,menu)`; `site_id=0` — портал. `/admin/menu` GET/PUT ограничен организацией пользователя; фиксированные ключи разделов, редактируемые названия kk/ru, порядок и видимость. До первого сохранения учитываются `organizations.hidden_sections`; затем сохранённое меню — источник навигации. Сохранение также обновляет legacy hidden_sections.
- `/admin/users`: управление сотрудниками только центральным администратором; центральные учётные записи защищены от изменений. `users.active` проверяется при входе и чтении сессии. Создание сотрудника не сбрасывает пароль существующего пользователя; сброс — отдельный endpoint по ID.
- `seed-demo` вызывает локальный `seed-news`: три кратких пересказа публикаций реальной школы №59 и два исходных фото. Источники и исходные даты в README; вымышленные организации остаются демо.
- Проверка обновления меню/пользователей: Go unit + интеграционный тест в отдельной пустой Docker PostgreSQL БД, `go vet ./...`, Vue production build / gzip-бюджет. Chromium 1440×1000 и 390×844: главная, пользователи, редактирование/перемещение меню с сохранением после reload. Снимки `output/playwright/updated-*.png`; мобильная ширина документа редактора меню — 390 px.
- Вложенное меню: `MenuItem.parent` (ключ группы или пустая строка), `group=true` для контейнера. До 3 уровней / 50 пунктов, стандартные страницы обязательны по одному разу; группы с ключом `group-*`. Сервер запрещает циклы, неизвестного/не-группового родителя и вложенную главную.
- Старый плоский JSON без поля `parent` группируется при чтении с сохранением названий, видимости и порядка соседей. Новый JSON всегда содержит `parent`; намеренное снятие всех групп не запускает повторную группировку. Миграция схемы не требуется.
- `NavMenu.vue` раскрывает дерево; `api.ts:menuTree` исключает скрытые группы и всех потомков. Редактор `/admin/menu`: создание/удаление групп, выбор родителя, порядок среди соседей, отображение уровней. При удалении группы страницы переходят к её родителю.

- `seed-school` (также после `seed-demo`) заполняет только `demo-school-51`: 23 публичных двуязычных материала, 13 фото Unsplash и 5 учебных PDF. Данные и источники в `fixtures/demo/school/content.json` / `photos.json`. Только DEV_HTTP/local domain; пароли, другие организации и меню не меняются.
- Завершение rich-school v2 определяется наличием вложений `demo-school-v2-*`; повторное заполнение сохраняет пользовательские правки. Прежние демо-записи сняты с публикации, about/schedule переиспользуются, ID прежнего PDF расписания сохранён. Фото людей — иллюстрации тестовых профилей, не реальные сотрудники.
- Проверки rich-school: Go unit/integration/vet и Vue production build; 23 опубликованные записи по разделам, повторное заполнение сохраняет правки/пароли. 5 PDF проверены отрисовкой и извлечением текста. Chromium: 8 разделов, загрузка фотографий, HTTP 200/PDF MIME документов и расписания; снимки `output/playwright/school-filled-*.png`.
- Rich-school проверена в Chromium на ширинах 1440 и 390 px: главная + 8 разделов без горизонтальной прокрутки, казахские карточки педагогов. Интеграционный тест дополнительно проверяет повторный seed после удаления обложки без её восстановления и без дублей.
- Авторизация школ: `/admin/` на собственном поддомене. При входе, чтении сессии и повторной блокирующей проверке логина `COALESCE(users.organization_id,0)` должен совпадать с организацией Host. Центральные учётные записи работают только на BASE_DOMAIN. Cookie без Domain; школьная панель не содержит выбора сайта.
- Проверены unit/integration/vet, Vue build; вход в свою школу, отказ на центральном/чужом Host, отказ при ручном переносе cookie, обязательная смена пароля, черновики/вложения, изоляция ID. Chromium: вход demo.school, сохранение собственного меню, отказ входа на чужом поддомене, сохранение своей сессии, мобильная панель 390 px. Снимки `output/playwright/school-admin-*.png`.
- Навигация админки: `AdminNavigation.vue` используется в desktop sidebar и мобильном native `<dialog>` при ширине до 900 px. Отдельные языковые вкладки редактора сохранены. Диалог закрывается после выбора раздела, по Escape и клику на фон; фокус возвращается к кнопке открытия. Школьные роли по-прежнему не видят пользователей/организации.
- Проверка sidebar: Vue typecheck / production build / gzip-бюджет, локальный Docker healthy. Chromium 1440×1000 и 390×844: переходы меню/педагоги/пользователи, активный раздел, Escape и возврат фокуса, отсутствие горизонтальной прокрутки страницы. Снимки `output/playwright/admin-sidebar-*.png`.
- URL меню: необязательный `MenuItem.url` у стандартных страниц, обязательный у дополнительных `link-*`; группы URL не имеют. Допустимы пути от `/` и HTTP(S) без userinfo, пробелов, управляющих символов, backslash и `//`. Пустое поле стандартной страницы использует прежний путь. Хранится в существующем JSON без миграции. `NavMenu.vue`: внешние адреса через `<a>`, внутренние через Vue Router.
- Проверены URL unit/integration (сохранение и публичный JSON, unsafe schemes), Go vet, Vue build и локальный Docker healthy. Chromium: создание вложенной ссылки, сохранение/reload, публичный href, удаление проверочного пункта; мобильная форма 390 px без горизонтальной прокрутки. Снимки `output/playwright/menu-url-*.png`.

- Тестовый сервер: SSH alias `zangar`, `/home/ubuntu/projects/school-test`, GitHub origin/main; `sh platform/scripts/deploy-test.sh` обновляет через fast-forward и Docker Compose. `deploy/compose.test.yaml` использует существующую сеть Traefik `zangar_edge`, BASE_DOMAIN=school.zangarengineering.kz, без DEV_HTTP. 13.10.2026 проверены HTTPS/сертификат, HTTP 301, главная/admin/healthz 200, Go tests и Vue build. Основные пароли находятся вне Git в закрытом каталоге сервера; не читать/выводить. После резервной копии выполнен seed-demo в отдельном CLI-процессе с локальными DEV_HTTP/BASE_DOMAIN; рабочий API остаётся без DEV_HTTP. Тестовые учётные записи используют общедоступный пароль fixtures; admin сохранён. Школьные поддомены требуют собственных Traefik Host-правил/сертификатов; добавлены точные роутеры для demo-school-51, demo-school-52, demo-preschool-7 и demo-disabled.

- После появления wildcard DNS проверены действительные HTTPS-сертификаты и HTTP 200 для трёх активных демо-сайтов; отключённая организация возвращает 404. Фото школы №51 и пять PDF доступны с правильными MIME.

- Баннеры: content.kind=banners, только для организаций; загрузки через существующий content_id с проверкой владельца, только JPEG/PNG/WebP до 10 МБ. Раздел панели /admin/banners; опубликованные изображения на главной переключаются вручную в порядке записей/файлов, без баннеров используется прежняя about-обложка. 001.sql повторно применима и расширяет content_kind_check. Проверены Go unit/vet и Vue typecheck/build/gzip; интеграционный сценарий публикации/изоляции добавлен, запуск требует отдельной пустой TEST_DATABASE_URL.

- Корневой Makefile: help/install/check/local-up/local-down/local-logs/deploy/deploy-status/deploy-logs. deploy требует clean main и HEAD=origin/main после fetch, затем вызывает существующий скрипт через SSH zangar; серверный скрипт требует main. Проверены make help/dry-run, shell syntax и отказ deploy при незакоммиченных изменениях.
